# libghostty-vt vs vTerm's xterm.js - test results

- When: 2026-11-18 9:02 PM on KRAKENAMD (16 logical CPUs), Windows 10.0.26300.0
- Terminal size 120 x 40, Cascadia Mono 13, scrollback 10,000 lines. Each workload 16 MB of UTF-8; median of 3 runs where repeated.
- libghostty-vt 1.0.1 (the release DLL) with the bench's WPF renderer (`GhosttyView`); xterm.js = vTerm's own copy (DOM renderer, Unicode 11 add-on) in WebView2 (a new WebView2 profile: first-ever start).

Workloads:
- **plain** - plain ASCII log lines (cat of a big log) (16.0 MB)
- **colour** - a colour change every few words (ls --color, coloured logs, git diff) (16.0 MB)
- **unicode** - accents, CJK, emoji and box drawing (wide characters) (27.7 MB)
- **fullscreen** - a full-screen app redrawing (htop / vim / Claude Code): cursor moves + colours (16.0 MB)

## Start-up (to a terminal on screen)

| | libghostty-vt + WPF | xterm.js in WebView2 |
|---|---:|---:|
| Time to the first frame | 296.6 ms (library + renderer 83.3 ms; the rest is WPF's first window, which vTerm pays either way) | 2433.1 ms (page ready 2390.9 ms) |
| Memory for one idle terminal | +35.3 MB in the process (mostly WPF's first window, which vTerm has either way) | 134.3 MB in WebView2's own processes |
